# Release Notes 0.2.0

Релиз итоговой функции капстоуна. Оформление заказа перестало быть заглушкой: теперь покупатель проходит полный путь «каталог → корзина → оформление → подтверждение заказа» на стороне клиента.

## Что нового

- **Оформление заказа.** Форма доставки с валидацией имени, телефона, email и адреса: ошибки появляются только после касания поля, кнопка «Оформить заказ» неактивна, пока форма невалидна.
- **Способ оплаты.** Обязательный выбор из трёх вариантов: картой при оформлении, наличными при получении, онлайн-перевод. Оформление без выбранного способа невозможно.
- **Экран подтверждения.** После отправки формы — итоговый состав заказа с ценой каждой позиции, общая сумма, способ оплаты и контактные данные. Корзина очищается.
- **Корректный итог.** Сумма подтверждения берётся из корзины (с учётом промокода и доставки) в момент отправки и замораживается — редактирование корзины после оформления не влияет на подтверждение.

## Для команды

- Спецификации капстоуна в `docs/specs/capstone/`: контракт приёмки, архитектурные решения, реестр рисков с мерами.
- Тесты: юнит для чек-аута и снапшота заказа + e2e-сценарий полного флоу (`tests/e2e/checkout.spec.js`).
- Ревью кода: `docs/capstone-review.md`.

## Известные ограничения

- Заказ не отправляется на сервер и не сохраняется между сессиями: снапшот живёт в памяти, перезагрузка страницы сбросит подтверждение.
- Выбор способа оплаты декоративный — реальный платёж не инициируется.
- На подтверждении показывается итог, но не отдельная детализация «доставка / скидка по промокоду».

# Release Notes 0.1.0

Учебный релиз магазина: каталог с фильтрами, корзина с промокодом, интеграция с API поставщика, MCP-инструменты для агента, тесты и подготовка релиза.

## Что нового

Каталог подключён к API поставщика. Приложение загружает товары по сети и переживает сбои: при ошибке сервера показывает кешированные данные, при полной недоступности — сообщение с кнопкой повторной загрузки. В редакторе подключён Playwright MCP — агент сам запускает e2e-тесты после изменений.

## Улучшения

- Скелетон загрузки вместо пустого экрана при ожидании данных.
- Четыре состояния каталога: `loading`, `retrying`, `fallback`, `failed`.
- Документация проекта: расширенный README, архитектурные решения, JSDoc для API-функций.

## Исправления

- Расчёт стоимости доставки учитывает скидку по промокоду.
- Адаптер каталога валидирует обязательные поля товара.

## Известные ограничения

- Кеш данных в localStorage ограничен ~5 МБ.
- Мок-API возвращает статические данные.
- Изображения товаров — плейсхолдеры.
