# Запрос на слияние: релиз 0.2.0

## What
Реализована итоговая функция капстоуна — полноценное оформление заказа. Ветка `feat/order` достраивает существующую заглушку до сквозного флоу: форма доставки с валидацией (имя, телефон, email, адрес), обязательный выбор способа оплаты (`card` / `cod` / `online`), экран подтверждения с составом корзины и итоговой суммой.

Заказ формируется целиком на клиенте: снапшот снимается чистой функцией `buildOrderSnapshot` в момент отправки формы и замораживает состав и итог, чтобы подтверждение не расходилось с корзиной. Изменения по контракту `docs/specs/capstone/contract.md`, без новых зависимостей и эндпоинтов. В комплекте — спецификации (contract, architecture, risk-register), юнит- и e2e-тесты, ревью кода и обновлённый README.

## Why
В 0.1.0 оформление заказа было заглушкой: пользователь доходил до корзины, но заказать не мог. Итоговая функция замыкает путь покупателя «каталог → корзина → оформление → подтверждение» на стороне клиента. Требования зафиксированы в контракте капстоуна (`docs/specs/capstone/contract.md`): валидация полей в `docs/checkout-validation-spec.md`, критерии приёмки и out-of-scope (без серверной отправки, без платёжных шлюзов, без localStorage для заказа).

## How to test

1. Склонировать ветку `feat/order`.
2. `npm install && npm run quality` — тесты, линтер, сборка без ошибок.
3. `npm run test:e2e` — сквозной сценарий оформления проходит вместе с существующими сценариями каталога и корзины.
4. `npm run dev` — добавить товар в корзину, перейти на `/checkout`.
5. Заполнить форму, **не выбирая** способ оплаты — кнопка «Оформить заказ» disabled и под полем способа оплаты появляется ошибка «Выберите способ оплаты».
6. Выбрать способ оплаты, отправить форму — открывается экран подтверждения с составом корзины и итогом, корзина очищена.
7. Открыть `/checkout` на новой вкладке при пустой корзине — вместо формы заглушка «Корзина пуста».

## Risks

- **Заказ не покидает сессию:** нет серверной отправки и оплаты. Снапшот живёт в памяти — `F5` на подтверждении сбросит заказ. Осознанное out-of-scope контракта, не баг.
- **Выбор способа оплаты декоративный:** с оплатой интерфейс не связывается, реальный платёж не инициируется.
- **Единый источник итога:** `total` берётся только из `useCart.getTotal()` до снятия снапшота, чек-аут не дублирует расчёт — расхождение с корзиной исключено, но любое изменение логики корзины влияет на подтверждение.
- **Контакты в снапшоте:** `buildOrderSnapshot` возвращает только `{ orderItems, total }`, контакты собираются в `CheckoutPage` — функция не валидирует их формат.
- Полный реестр рисков и меры по каждому — `docs/specs/capstone/risk-register.md`.
