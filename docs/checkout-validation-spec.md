# Валидация формы оформления — feature spec

Добавляем клиентскую валидацию в `OrderForm`. Цель: не давать отправить форму с пустыми или некорректными полями, показывать ошибки рядом с полями, поддерживать доступность.

## Scope

- Валидация четырёх полей: имя, телефон, email, адрес.
- Инлайновые сообщения об ошибках рядом с каждым полем.
- Кнопка «Оформить заказ» disabled, пока есть ошибки.
- Валидация на `onBlur` после первого касания поля и на `onSubmit`.
- `aria-invalid`, `aria-describedby`, `role="alert"` для доступности.

## Out-of-scope

- Серверная валидация. Считаем, что бэкенд — отдельный этап.
- Форматирование телефона по маске (пока принимаем «голый» формат).
- Проверка email через DNS-запросы.
- Автозаполнение адреса через API.
- Сохранение черновика формы в localStorage.

## Constraints

- Не менять структуру `cartItems` и `onSubmit` контракт компонента.
- Не добавлять внешние библиотеки валидации (react-hook-form, formik).
- Использовать только React hooks, без сторонних state-менеджеров.

## Правила валидации

| Поле | Правило | Сообщение ошибки |
|---|---|---|
| `name` | Непустая строка, ≥ 2 символов после trim | «Введите имя» / «Имя слишком короткое» |
| `phone` | `^\+?[0-9]{10,15}$` после удаления пробелов и скобок | «Введите телефон» / «Телефон в формате +7XXXXXXXXXX» |
| `email` | `^[^\s@]+@[^\s@]+\.[^\s@]+$` | «Введите email» / «Некорректный email» |
| `address` | Непустая строка, ≥ 5 символов после trim | «Введите адрес доставки» / «Адрес слишком короткий» |

## Поведение

Ошибка под полем появляется в двух случаях: покупатель ушёл из поля, которого уже касался, или нажал «Оформить заказ». На нетронутой форме ошибок нет — пустые поля не подсвечиваются, пока покупатель до них не дошёл.

Исчезает ошибка сразу, как только поле стало валидным: следующая проверка этого поля убирает сообщение, остальные поля остаются как были.

Кнопка «Оформить заказ» неактивна, пока хоть одно поле содержит ошибку. Форма уходит только когда валидны все четыре: тогда `onSubmit` получает данные формы и товары корзины.

## Acceptance criteria

1. **Пустая форма → submit.** При клике «Оформить заказ» на пустой форме появляются ошибки под всеми четырьмя полями. `onSubmit` не вызывается.
2. **Частично заполненная форма.** Заполнение одного поля не убирает ошибки с других полей; кнопка остаётся disabled.
3. **onBlur после первого касания.** Поле показывает ошибку только после того, как пользователь впервые его коснулся (touched). Не спамим ошибками на пустой форме.
4. **Корректные данные.** Когда все четыре поля валидны, кнопка активна, `onSubmit` вызывается с данными формы и товарами.
5. **Доступность.** У полей с ошибкой `aria-invalid="true"` и связь через `aria-describedby` с сообщением. Сообщения имеют `role="alert"`.
6. **Формат телефона.** `+7 999 123 45 67`, `+79991234567`, `89991234567` принимаются. `abc`, `123` — нет.
7. **Формат email.** `test@example.com` принимается. `test@`, `test@.com`, `@test.com` — нет.
