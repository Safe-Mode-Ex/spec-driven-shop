# Архитектурные решения — оформление заказа (capstone)

> Решения, которые повлияют на дизайн модуля. Каждый компромисс документирован: какие были варианты, что выбрали и почему. Это для будущей команды (и нас через полгода) — чтобы не пересматривать каждое решение заново.

## A1. Выбор способа оплаты: перечисление + отдельный компонент

**Options.**
- A. Инлайн-разметка радиокнопок прямо в `OrderForm.jsx` с локальным строковым состоянием.
- B. Перечисление методов (`card` / `cod` / `online`) как константа-объект + отдельный компонент `PaymentMethodSelect.jsx`, управляемый через пропсы `selected` / `onChange`.
- C. Дропдаун `<select>` для выбора способа.

**Decision.** Вариант B.

**Rationale.** Три варианта — подходящий случай для радиогруппы, семантически верной и доступной из коробки (`fieldset`/`legend`). Вынос в компонент сохраняет `OrderForm` читаемым и позволяет тестировать оплату отдельно от контактных полей. Перечисление константой — единственный источник допустимых значений, защищает от опечаток в `payment.method` (проверяется в `buildOrderSnapshot`). Дропдаун скрывает параметры и хуже для трёх коротких вариантов. Инлайн-разметка смешивает ответственности и усложняет тест приёмки «оплата обязательна».

## A2. Снапшот заказа — чистая функция, а не код компонента

**Options.**
- A. Собирать объект заказа прямо в `CheckoutPage`/`OrderForm` при `onSubmit`.
- B. Чистая функция `buildOrderSnapshot(cartItems, contact, payment)` в `src/utils/order.js`, компонент вызывает её и передаёт результат в подтверждение.
- C. Класс/модуль-сервис с состоянием заказа.

**Decision.** Вариант B.

**Rationale.** Логика снапшота — чистая: из «сырых» данных корзины, контактов и оплаты делает слепок с копиями товаров. Чистая функция легко покрывается юнит-тестами (не мутирует `cartItems`, валидирует `payment.method`, корректно считает состав и итог) и переиспользуется. Сборка в компоненте смешивает состояние UI и бизнес-логику и не тестируется без рендера. Класс-сервис избыточен: у функции нет внешних зависимостей и жизненного цикла. Функция **не** считает итог — берёт `total` из корзины (`useCart.getTotal()`), чтобы не было второго источника правды.

## A3. Экран подтверждения — локальное состояние, а не отдельный маршрут

**Options.**
- A. `/checkout/success` как новый маршрут в `App.jsx`, состояние заказа передавать через `location.state` (react-router) или URL-параметры.
- B. Локальное состояние `orderPlaced` в `CheckoutPage`; подтверждение — условный рендер вместо формы.
- C. Внешний стейт (Redux/Zustand) для «текущего заказа».

**Decision.** Вариант B.

**Rationale.** Подтверждение должно отображаться сразу после отправки, без перезагрузки страницы. Локальное состояние проще и не добавляет маршрутов: `F5` на странице сбросит заказ — для учебного проекта (заказ не сохраняется в localStorage, нет истории) это приемлемо. Маршрут `/checkout/success` понадобился бы, если бы заказ отправлялся на сервер и был номер/подтверждение извне — сейчас этого нет, а передача состояния через `location.state` ломается на прямом заходе по URL. Внешний стейт противоречит принципу «минимум зависимостей» в AGENTS.

## A4. Состояние формы — `useState`, без библиотек форм

**Options.**
- A. `useState` для `formData`, `errors`, `touched`, как в текущей заглушке.
- B. `useReducer` для централизации обработки полей/ошибок.
- C. Форма-библиотека (react-hook-form, formik).

**Decision.** Вариант A.

**Rationale.** Форма уже реализована на `useState` и покрыта критериями приёмки; добавлять reducer ради четырёх полей и одной радиогруппы — преждевременно. Библиотеки форм — новые зависимости, запрещённые AGENTS.md («без явного запроса»), и избыточны для объёма. Оставляем существующую модель состояния и расширяем её одним полем `payment.method` через тот же паттерн (`formData`/`errors`/`touched`).

## Структура файлов (итоговая)

```
src/
  utils/
    order.js                          # buildOrderSnapshot(cartItems, contact, payment)
    __tests__/
      order.test.js
  features/checkout/
    CheckoutPage.jsx                  # оркестратор: форма <-> подтверждение
    OrderConfirmation.jsx             # экран подтверждения
    PaymentMethodSelect.jsx           # радиогруппа способа оплаты
    OrderForm.jsx                     # форма доставки + оплата (дорабатывается)
    __tests__/
      OrderForm.test.jsx
      PaymentMethodSelect.test.jsx
```

## Константы

- Методы оплаты: `PAYMENT_METHODS = { card, cod, online }` рядом с `PaymentMethodSelect`/`order.js` (в границах `src/features/checkout/` и `src/utils/`), не в общем `constants.js`.
- Валидация оплаты в снапшоте: `payment.method` должен быть одним из трёх значений, иначе — ошибка.
