# Контракт API каталога

Единственный источник правды о внешнем сервисе. Если в коде появляется поле или код ошибки, которого нет здесь, — это либо баг, либо пора обновлять контракт.

## Scope

Подключение каталога товаров к API поставщика. Загрузка списка товаров, фильтрация по категории, обработка ошибок и фолбэк на кеш.

## Out-of-scope

- Загрузка карточки одного товара (отдельный эндпоинт, появится позже).
- Поиск, сортировка, серверная фильтрация по цене.
- Корзина и оформление заказа.

## Базовый URL

`https://supplier.example.com/api/v2`

В коде используется относительный путь `/api/v2`, разворачиваемый от `window.location.origin`.

## Эндпоинт

### GET /products

Список товаров каталога.

**Авторизация.** Заголовок `X-Api-Key: ${VITE_API_KEY}`. Переменная окружения, не коммитится.

**Параметры запроса:**

| Параметр | Тип | Обязательность | Значения |
|---|---|---|---|
| `category` | string | опционально | `Одежда` \| `Обувь` \| `Аксессуары` |
| `page` | int | опционально | по умолчанию 1 |
| `limit` | int | опционально | 1..50, по умолчанию 20 |

**Успешный ответ (200):**

```json
{
  "items": [
    {
      "item_id": 1,
      "item_name": "Футболка",
      "item_price": 1490,
      "in_stock": true,
      "category": "Одежда",
      "discount": 20,
      "image": "/products/tshirt.svg",
      "description": "Футболка из плотного хлопка"
    }
  ],
  "total": 6,
  "page": 1
}
```

**Формат ошибки (4xx/5xx):**

```json
{
  "error": {
    "code": "string",
    "message": "string"
  }
}
```

Если ответ пришёл со статусом ошибки, но тело не в этом формате (HTML-страница, пустое тело) — `INVALID_RESPONSE`.

## Коды ошибок

| Код | Что значит | Повторять? |
|---|---|---|
| 400 | Неверные параметры запроса | Нет, баг в нашем коде |
| 401 | Невалидный API-ключ | Нет, ошибка конфигурации |
| 404 | Ресурс не найден | Нет |
| 429 | Превышен лимит запросов | Нет. Сразу к фолбэку; `Retry-After` сохраняется в ошибке как подсказка |
| 500-503 | Ошибка сервера | Да, до 3 попыток |
| Таймаут | Сеть не ответила за 5 с | Да, до 3 попыток |

## Маппинг полей в наш домен

Поставщик использует snake_case. Внутри приложения — camelCase. Адаптер (`adaptProduct` в `src/api/catalog-adapter.js`) делает трансформацию:

| API (исходный) | Приложение (адаптировано) |
|---|---|
| `item_id` | `id` |
| `item_name` | `name` |
| `item_price` | `price` |
| `in_stock` | `inStock` |
| `category` | `category` |
| `discount` | `discount` |
| `image` | `image` |
| `description` | `description` |

## Acceptance criteria

1. `npm test` проходит. Покрыты сценарии: основной сценарий, таймаут, 5xx, фолбэк на кеш, `INVALID_RESPONSE`.
2. `ApiError` — единственный тип ошибки, который вылезает наружу из модуля.
3. Интерфейс отображает четыре состояния: `loading`, `retrying`, `fallback`, `failed`.
4. `VITE_USE_MOCK_DATA=true` переключает источник без пересборки.
5. `VITE_API_KEY` нигде не коммитится. `.env` в `.gitignore`, `.env.example` с пустым значением.
6. `npm run lint` без ошибок уровня error. `npm run build` без ошибок.

## Quality gates (секция контракта)

Допуск к слиянию:

- [x] `npm test` зелёный, покрыты все четыре базовых сценария + сценарий R7 (изменение формата ответа).
- [x] `npm run lint` без ошибок.
- [x] `npm run build` без ошибок.
- [x] Прогнан сценарий «API работает»: каталог загружается, показывает товары.
- [x] Прогнан сценарий «API недоступен» (отключить сеть в DevTools): после таймаута видны кешированные данные с пометкой.
- [x] Прогнан сценарий «API недоступен, кеша нет» (очистить localStorage): сообщение об ошибке и кнопка повторного запроса.
- [x] Прогнан сценарий с `VITE_USE_MOCK_DATA=true`: каталог показывает моки без обращения к API.

## Rollback (секция контракта)

### Уровень 1. Переключатель на мок-данные (минутный откат)

**Когда применять:** поставщик недоступен надолго, невалидный ответ массово ломает UI.

**Как применять:**

1. В переменных окружения продакшена выставить `VITE_USE_MOCK_DATA=true`.
2. Запустить повторное развёртывание (или обновление на лету, если переменная читается из внешнего конфига).
3. Проверить главную страницу — должны отображаться товары из `src/api/mocks/catalog.json`.

**Ограничение:** пользователи увидят набор тестовых товаров. Не стоит держать дольше часа.

### Уровень 2. Возврат предыдущего релиза

**Когда применять:** баг в нашем коде (адаптер сломал парсинг, логика повторов уводит в бесконечный цикл).

**Как применять:**

1. В CI/CD найти последний зелёный релиз до интеграции.
2. Откатиться к предыдущему релизу через пайплайн.
3. Проверить в тестовой среде, что проблема ушла.
4. Развернуть в продакшен.

### Триггеры отката

- Доступность каталога ниже 95% за последний час.
- Доля ошибок запросов выше 30% за последние 10 минут.
- Массовые жалобы пользователей в поддержку на пустой/сломанный каталог.

## Что НЕ поддерживается контрактом

- Фильтрация по цене на сервере. Делаем на клиенте после загрузки страницы.
- Сортировка. На клиенте.
- Поиск по названию. На клиенте.
- Вебхуки или SSE для обновления в реальном времени.
