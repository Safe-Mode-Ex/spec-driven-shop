# Risk checklist 0.2.0

Заполнен для релиза капстоуна — итоговой функции оформления заказа. Базируется на ветке `feat/order`. Каждый риск из `docs/specs/capstone/risk-register.md` отмечен статусом:
- **Закрыт** — мера реализована и проверена тестом/ревью.
- **Принят** — осознанное ограничение scope, живёт как есть.
- **Отложен** — перенесён в следующий релиз.

Дата: 2026-09-07
Ветка: `feat/order`

## Технические риски

| # | Риск | Статус | Чем закрыт / почему принят |
|---|---|---|---|
| T1 | Корзина пуста при переходе на `/checkout` | Закрыт | `CheckoutPage` проверяет `items.length === 0` и не рендерит форму; критерий приёмки 1, тест компонента |
| T2 | Корзина изменилась между формой и подтверждением | Закрыт | Снапшот снимается в момент отправки формы; состав и итог заморожены в копиях через `buildOrderSnapshot` |
| T3 | Итог подтверждения расходится с корзиной | Закрыт | Единственный источник `useCart.getTotal()` вызывается до снятия снапшота; `order.js` не пересчитывает цены; критерий приёмки 6, юнит-тест |
| T4 | `buildOrderSnapshot` мутирует входной массив | Закрыт | Копии товаров через map/spread; юнит-тест проверяет неизменность исходных `cartItems` |
| T5 | Невыбранный способ оплаты пропускается | Закрыт | Нет значения по умолчанию; ошибка «Выберите способ оплаты»; критерии приёмки 2 и 4, кнопка disabled |
| T6 | Передан невалидный `payment.method` | Закрыт | Валидация в `buildOrderSnapshot` против `PAYMENT_METHODS`; функция бросает ошибку; юнит-тест на каждый невалидный случай |
| T7 | Пустой список при непустой «живой» корзине (гонка) | Закрыт | `OrderConfirmation` рендерит состав только из снапшота; заглушка «Состав заказа пуст», без падения |
| T8 | Цены в снапшоте устарели (промокод применён/отменён) | Закрыт | Итог пересчитывается `useCart.getTotal()` в момент submit; логика скидок не дублируется в чек-ауте |

## Процессные риски

| # | Риск | Статус | Чем закрыт / почему принят |
|---|---|---|---|
| P1 | Агент генерирует код за пределами контракта | Закрыт | Контракт фиксирует out-of-scope; ревью сверяет код с критериями приёмки |
| P2 | Зелёные моки, сломанные реальные данные | Закрыт | e2e прогоняет полный флоу на реальном приложении; юнит-тесты работают с реальной структурой `cartItems`; критерий приёмки 9 (без сети) |
| P3 | Регресс существующего оформления (заглушки) | Закрыт | Роллбэк уровня 1 (форма без `PaymentMethodSelect`); существующие e2e корзины и каталога не тронуты; `npm run quality` перед слиянием |
| P4 | Дублирование логики итога в корзине и чек-ауте | Закрыт | Архитектура A2/A3: единственный источник `getTotal()`; в ревью проверено, что `order.js` не считает цены/скидки |
| P5 | Сползание границ задачи агентом | Закрыт | Границы зафиксированы в AGENTS.md; изменения — только `src/features/checkout/`, новый `src/utils/order.js` и их тесты |
| P6 | Нарушена доступность радиогруппы оплаты | Закрыт | `fieldset`/`legend`, нативные radio, `aria-invalid`/`aria-describedby`; критерий приёмки 8, компонент-тест разметки |

## Принятые ограничения

| Риск | Статус | Обоснование |
|---|---|---|
| Заказ не отправляется на сервер, номер заказа не выдаётся | Принят | Осознанный out-of-scope контракта: заказ на сессию; после перезагрузки вернуться к нему нельзя |
| На подтверждении нет детализации «доставка / скидка по промокоду» | Принят | Разбивка стоимости — ответственность корзины, там она уже есть |
| Способ оплаты не инициирует реальный платёж | Принят | Учебное ограничение, зафиксировано в out-of-scope |

## Выводы

Шесть технических и шесть процессных рисков капстоуна закрыты мерами и тестами. Три ограничения приняты как осознанный scope. Отложены две проверки без практических последствий в текущем релизе. Перед слиянием: `npm run quality` зелёный, e2e-сценарий оформления проходит вместе с существующими.
