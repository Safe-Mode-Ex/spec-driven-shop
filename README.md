# HTML Academy Shop

Учебный интернет-магазин курса «[Разработка с AI-агентами: инженерный подход](https://up.htmlacademy.ru/ai/2)». Релиз 0.1.0: каталог, корзина с промокодом, оформление заказа, интеграция с API поставщика, сквозные тесты через Playwright MCP, релизный пакет.

## Что делает проект

SPA-магазин с тремя экранами:

1. **Каталог** — список товаров с фильтрацией по категории (Одежда / Обувь / Аксессуары). Данные загружаются из API поставщика или берутся из встроенных статических данных.
2. **Корзина** — добавление / удаление товаров, изменение количества, применение промокодов (скидка 10 % на «promocode10»), подсчёт итоговой стоимости.
3. **Оформление заказа** — форма с валидацией (ФИО, email, телефон, адрес), отправка заказа, экран подтверждения.

При обращении к реальному API каталог поддерживает четыре состояния интерфейса: `loading`, `retrying` (повтор с нарастающей задержкой), `fallback` (данные из кеша localStorage), `failed` (ошибка с кнопкой «Повторить»).

## Переменные окружения

Скопировать `.env.example` в `.env`:

```bash
cp .env.example .env
```

| Переменная | Описание | По умолчанию |
|---|---|---|
| `VITE_USE_MOCK_DATA` | `true` — встроенные данные; `false` — запросы к API поставщика | `true` |
| `VITE_API_KEY` | Ключ API поставщика (нужен при `VITE_USE_MOCK_DATA=false`) | (пусто) |

> **Для разработки** ключ не нужен — проект работает целиком на моках.  
> **Для проверки интеграции** установите `VITE_USE_MOCK_DATA=false` и заполните `VITE_API_KEY`.

## API-интеграция

### Эндпоинт

```
GET /api/v2/products
```

Базовый URL берётся из `window.location.origin` (относительный путь `/api/v2`). В продакшене проксируется через бэкенд или CDN.

### Авторизация

Заголовок: `X-Api-Key: ${VITE_API_KEY}`

### Параметры запроса

| Параметр | Тип | Обязательность | Описание |
|---|---|---|---|
| `category` | string | опционально | `Одежда` · `Обувь` · `Аксессуары` |
| `page` | int | опционально | Номер страницы (по умолчанию 1) |
| `limit` | int | опционально | Товаров на странице, 1–50 (по умолчанию 20) |

### Формат ответа (200 OK)

```json
{
  "items": [
    {
      "item_id": "1",
      "item_name": "Кроссовки",
      "item_price": 4990,
      "in_stock": true
    }
  ],
  "total": 12,
  "page": 1,
  "limit": 20
}
```

### Адаптер данных

Адаптер `adaptProduct` (в `src/api/catalog-adapter.js`) преобразует внешний формат в доменную модель:

| Внешний формат (snake_case) | Доменная модель (camelCase) |
|---|---|
| `item_id` | `id` |
| `item_name` | `name` |
| `item_price` | `price` |
| `in_stock` | `inStock` |

### Обработка ошибок

| Тип ошибки | Константа `ErrorType` | Поведение |
|---|---|---|
| Сеть | `NETWORK` | Ретрай × 3 с экспоненциальной задержкой |
| Таймаут (5 с) | `TIMEOUT` | Ретрай × 3 с экспоненциальной задержкой |
| Лимит запросов | `RATE_LIMIT` | Ретрай × 3 с экспоненциальной задержкой |
| Сервер (5xx) | `SERVER` | Ретрай × 3 с экспоненциальной задержкой |
| Клиент (4xx) | `CLIENT` | Без ретрая, переход в `failed` |
| Невалидный ответ | `INVALID_RESPONSE` | Без ретрая, переход в `failed` |

После исчерпания попыток интерфейс переходит в состояние `fallback` (кеш localStorage) или `failed`.  
Полная спецификация контракта — `docs/specs/api-catalog/contract.md`.

## Сквозные тесты

Лежат в `tests/e2e/`, конфигурация — `playwright.config.js`.

```bash
npm run test:e2e
```

Тесты запускаются на локальном dev-сервере. Через Playwright MCP агент может открывать страницы, кликать по элементам, заполнять формы и делать скриншоты прямо из диалога.

## API-интеграция

Каталог товаров загружается через `GET /api/v2/products` с заголовком `X-Api-Key: ${VITE_API_KEY}`. Адаптер `adaptProduct` преобразует snake_case формат поставщика в доменную модель. Интерфейс поддерживает четыре состояния: `loading`, `retrying` (повтор с нарастающей задержкой), `fallback` (кеш из localStorage с пометкой), `failed` (ошибка с кнопкой «Повторить»). Полная спецификация — `docs/specs/api-catalog/contract.md`.

## MCP

Подключён [Playwright MCP](https://github.com/microsoft/playwright-mcp) — агент в редакторе сам открывает страницы, нажимает на элементы, заполняет формы, делает снимки экрана и читает консоль, запуская тесты прямо из диалога. Конфигурация — `.cursor/mcp.json`. Политика подтверждений по типам инструментов и полный список — `docs/mcp-inventory.md`, `docs/mcp-risk-log.md`. Первый запуск скачает браузерное ядро Chromium (~300 МБ).

## Сквозные тесты

Лежат в `tests/e2e/`, конфигурация — `playwright.config.js`. Запуск:

```bash
npm run test:e2e
```

Тесты выполняются на локальном сервере разработки. Запустить их может и агент через Playwright MCP.
