# Журнал изменений

Все заметные изменения проекта документируются в этом файле.
Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## [0.2.0] - 2026-09-07

Итоговая функция капстоуна: полное оформление заказа — форма с валидацией, выбор способа оплаты, экран подтверждения с составом и итогом. Заказ формируется целиком на клиенте и не покидает сессию.

### Добавлено

- Полное оформление заказа: форма доставки с валидацией имени, телефона, email и адреса (touched-поля, `aria`-связи для доступности).
- Выбор способа оплаты через радиогруппу `PaymentMethodSelect`: `card` / `cod` / `online`, обязательный выбор.
- Экран подтверждения заказа со составом корзины, итоговой суммой, способом оплаты и контактными данными.
- Чистая функция снапшота `buildOrderSnapshot` в `src/utils/order.js` — замораживает копии товаров и итог в момент отправки формы.
- Очистка корзины после оформления (`clearCart` в `CartContext`).
- Спецификации капстоуна: `docs/specs/capstone/` (contract, architecture, risk-register) и ревью кода.
- Комплект тестов: юнит-тесты чек-аута и снапшота, e2e-сценарий оформления (`tests/e2e/checkout.spec.js`).

### Изменено

- `CheckoutPage` стал оркестратором флоу: форма при непустой корзине, подтверждение после отправки, заглушка при пустой.
- `OrderForm` расширен выбором способа оплаты; кнопка «Оформить заказ» disabled до валидной формы.
- README и `vitest.config.js` расширены под новую функцию и e2e-исключения (Vitest не подхватывает `tests/e2e/`).

### Исправлено

- Заказ нельзя отправить без выбранного способа оплаты — раньше форма принимала заказ без него.
- Пустая корзина на `/checkout` показывает заглушку «Корзина пуста» вместо пустой формы.
- Состав и итог на подтверждении заморожены в момент отправки и не меняются при последующем редактировании корзины.

## [0.1.0] - 2026-04-13

Учебный релиз магазина: каталог, корзина, промокод, интеграция с API, MCP, тесты и подготовка релиза. В дальнейшем добавится выбранная итоговая функция.

### Добавлено

- Интеграция с API поставщика для каталога товаров.
- Обработка ошибок API: таймаут, ошибки сервера, rate limit.
- Фолбэк на кешированные данные при недоступности API.
- Четыре состояния загрузки каталога: `loading`, `retrying`, `fallback`, `failed`.
- Скелетон загрузки каталога с анимацией.
- Playwright MCP для агентного запуска e2e-тестов.
- Инвентаризация MCP-инструментов и реестр рисков.
- Расширенная документация: README, журнал решений, JSDoc для API.

### Изменено

- Каталог загружает товары через API вместо статического файла.
- Промокод сохраняется в localStorage между сессиями.

### Исправлено

- Корректный расчёт доставки при применении промокода (учитывается сумма после скидки).
- Валидация полей товара в адаптере предотвращает отображение неполных данных.
